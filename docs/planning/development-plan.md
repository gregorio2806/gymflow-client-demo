# Development Plan

How we build the MVP: in small vertical slices, each one working end-to-end (migration → model → policy → controller → Vue page → tests) before starting the next.

Spec: [project-blueprint.md](../product/project-blueprint.md) · Rules: [AGENTS.md](../../AGENTS.md)

---

## How we work

1. **One phase at a time.** Don't start Phase N+1 until Phase N's "Done when" list is checked.
2. **Every feature ships with tests** — including a cross-tenant test (Gym B can't touch Gym A's data).
3. **Commit small and often** on a feature branch (`feature/members-crud`), merge to `main` when tests pass.
4. **Run before every commit:** `php artisan test`, `vendor/bin/pint` (PHP formatting), `npm run check` (JS lint + format), `npm run types:check`.
5. **Update AGENTS.md** when something a new developer must know changes (accounts, commands, rules).
6. Check the relevant docs checklist ([security](../engineering/security.md), [performance](../engineering/performance-and-reliability.md), [accessibility](../design/accessibility-and-content.md)) when a feature touches that area.

## Task loop (for humans and AI agents)

Work through a phase's task list **one task at a time**. For each task, follow this loop strictly:

1. **Implement**
    - Read the task and any related existing code before writing anything.
    - Make the smallest change that fully completes the task.
    - Follow the existing project conventions (Laravel backend, Vue + Inertia frontend).
2. **Test**
    - Write or update tests that cover the task (Pest Feature/Unit tests; Vue component tests if they exist).
    - Run `php artisan test`. If frontend files changed, also run `npm run build`.
    - Run lint/type checks: `vendor/bin/pint --test`, `npm run check`, `npm run types:check`.
3. **Verify**
    - All green → short summary of what changed and which tests cover it, then move to the next task.
    - Failing → fix the cause and re-run. **Never move on with failing tests.**
    - 3 failed attempts on the same task, or the task is unclear → **stop and ask** instead of guessing.

Rules:

- Only one task at a time. Don't start task N+1 until task N passes.
- Don't change or delete existing tests just to make them pass, unless the task requires it — and say so when you do.
- Don't modify unrelated files.
- After each task, report: **Task #, status (done/blocked), files changed, test result.**
- For UI changes, provide **concise STR** in the completion report and task entry: role → click path → example input/action → expected result. Assume the local app is running; skip repeated startup, known credentials, and routine login instructions. Include only feature-specific prerequisites or necessary role/account switches. Aim for 2–4 short steps, use fictional data, and briefly note record changes. Backend-only tasks should state there is no new UI.
- Tick the task in this file and update "Next steps" in [AGENTS.md](../../AGENTS.md).

## Folder conventions

Laravel's default structure, plus these additions (create folders when the first file needs them):

```
app/
├── Actions/                  # Business operations, one class each: RenewMembership, RecordPayment, CheckInMember
├── Http/
│   ├── Controllers/
│   │   ├── Dashboard/        # Owner/staff/coach app (Inertia + Vue)
│   │   ├── Portal/           # Member portal (Inertia + Vue)
│   │   ├── GymSite/          # Public gym websites (Blade)
│   │   ├── Platform/         # Platform admin
│   │   └── Settings/         # (starter kit) user profile/security
│   ├── Middleware/           # SetCurrentGym, ResolveGymFromSubdomain, SecurityHeaders
│   └── Requests/             # Form Requests, mirroring the controller folders
├── Models/
│   └── Concerns/             # BelongsToGym and other model traits
├── Policies/
├── Tenancy/                  # CurrentGym service
└── Enums/                    # MembershipStatus, GymRole, PaymentMethod, ...

resources/
├── js/                       # Vue + Inertia (starter kit layout)
│   ├── pages/
│   │   ├── dashboard/        # members/, plans/, attendance/, payments/, website/, reports/
│   │   ├── portal/
│   │   ├── platform/
│   │   ├── auth/             # (starter kit)
│   │   └── settings/         # (starter kit)
│   ├── components/           # Shared Vue components; ui/ = shadcn-vue primitives
│   ├── layouts/
│   ├── composables/
│   └── types/
└── views/
    ├── app.blade.php         # Inertia root (starter kit)
    ├── marketing/            # Blade platform landing page (no JS)
    ├── components/           # Blade components (icon.blade.php = inline Lucide SVGs)
    └── gym-site/             # Blade public gym website templates
        ├── layouts/
        └── pages/

routes/
├── web.php                   # Platform marketing + dashboard
├── settings.php              # (starter kit)
├── portal.php                # Member portal
└── gym-site.php              # Subdomain public websites

tests/
├── Feature/
│   ├── Tenancy/              # Cross-tenant isolation tests
│   ├── Dashboard/
│   ├── Portal/
│   └── GymSite/
└── Unit/                     # Date/status calculations, Actions

docs/                         # product/ planning/ design/ engineering/ legal/ learning/ — see docs/README.md
```

Naming: controllers singular resource (`MemberController`), Vue pages folder per resource (`pages/dashboard/members/Index.vue`, `Show.vue`, `Create.vue`, `Edit.vue`), Actions as verb phrases (`RenewMembership`).
